## 경력기술서 — HUINNO / Data Engineer (2025.12 ~ 재직 중)

```
의료 도메인과 온프레미스 MLOps를 스스로 학습하며, 요구사항 발굴과 기술 선정부터 하드웨어 구성·데이터 파이프라인 운영까지 주도했습니다.

[연구자 인터뷰에서 시작한 MLOps 신규 설계·구축]
· 연구자 인터뷰와 데이터·코드·실행 방식 분석으로 기존 작업의 병목을 수집했습니다. 각 노드에 데이터가 흩어져 있고, 생성·저장 방법이 일부 생산자의 암묵지로 관리되어 담당자 부재 시 데이터 확보가 어려웠습니다.
· 생성 코드는 버전 관리되지 않았고, 데이터는 SSH로 복사해 전달했습니다. 모델과 성능은 Notion에서 공유되어 데이터·코드·실행 환경을 연결한 재현 기반이 필요했습니다.
· 이를 자동 실행, 공용 저장소, 버전·계보 관리 요구사항으로 구체화했습니다. Airflow는 실행·재시도, dbt는 SQL 변환, Iceberg는 테이블 버전, DataHub는 계보 관리를 맡도록 기술별 역할을 설계했습니다.

[온프레미스 Kubernetes와 하드웨어 운용]
· 플랫폼 2인 팀에서 클러스터 구성을 단독 담당했습니다. 사내 장비로 10노드 베어메탈 Kubernetes를 구축하고 네트워크·스토리지·인증·실행 환경을 12개 Pulumi 스택으로 코드화했습니다(2026.09 기준).
· 유휴 PC·워크스테이션을 분해해 RAM·NVMe를 회수·재장착하고, 네트워크 장비 선정·교체를 직접 주도했습니다.
· NUMA·듀얼채널 구성, 메모리 압박·swap을 점검하고 PostgreSQL 데이터 디스크를 분리하는 등 실제 워크로드에 맞춰 하드웨어와 시스템을 함께 조정했습니다.

[공통 데이터 파이프라인과 SQL 조회 환경]
· Airflow·dbt 기반 Bronze/Silver/Gold 파이프라인과 DataHub 계보 기록을 구현했습니다. 공통 프레임워크, 연구용 데이터, MIMIC-IV, 운영 유지보수 ETL을 구축했습니다.
· SeaweedFS의 S3 호환 저장소와 Iceberg REST Catalog로 Silver/Gold 데이터·메타데이터를 관리하고 NVMe/HDD 티어를 구성했습니다.
· PostgreSQL + pg_duckdb 조회 환경을 마련했습니다. 차원 테이블 생성 시 카탈로그에서 최신 메타데이터 경로를 조회해 DuckDB에 전달하여, 파일명으로 버전을 추정하지 않고 카탈로그를 기준으로 데이터를 읽도록 구현했습니다.

[데이터 버전과 실험·모델 재현 기반]
· 데이터 버전·코드 커밋·환경 정보 등을 담은 manifest 동결·복원 도구와 검증 절차를 구현했습니다.
· MLflow 트래킹·모델 레지스트리와 SeaweedFS 아티팩트 저장소를 구축했습니다. 연구 코드 연동과 데이터부터 모델까지의 전체 재현 검증은 진행 중입니다.
· 누락 원본 데이터 재수집·무결성 검증과 환경별 서비스·버킷 분리를 적용했습니다.

[연구자와 플랫폼의 역할 분담]
· 연구자는 도메인 ETL을, 플랫폼은 실행·계보·검증·재시도를 담당하도록 경계를 정의했습니다. 후속 인터뷰로 도입 계획을 조율하고 있습니다.
· Dex/OIDC와 Kubernetes RBAC으로 접근 제어를 연결하고, KubeRay 공통 학습 환경을 구축해 연구 코드 이관을 지원하고 있습니다.
```

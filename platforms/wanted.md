# 원티드 (한국어)

경력기술서를 길게 받는 곳이라 **가장 상세한 판**이다. 기술 태그가 검색 축이라
스택을 따로 나열한다. 평문 입력란이므로 마크다운이 안 먹는다 — 블록을 그대로 복사한다.

---

## 한 줄 소개

```
온프레미스 Kubernetes 위에 사내 MLOps 파이프라인 전체를 혼자 설계·구축·운영한 데이터/플랫폼 엔지니어입니다. 도구를 늘리기보다 사람이 끼어 있던 자리를 없애는 데 관심이 있습니다. 인프라 스택 코드 변경의 93%, ETL 저장소 커밋의 83%를 직접 작성했습니다.
```

---

## 경력기술서 — HUINNO / Data Engineer (2025.12 ~ 재직 중)

```
사내 MLOps 파이프라인 전체를 처음부터 설계·구축·운영하고 있습니다.
수집 → 레이크하우스 → 변환 → 계보 → 분산 학습 → 실험·모델 레지스트리까지 전 구간입니다.

[소유 범위]
· 플랫폼 2인 팀에서 클러스터 구성 전 구간을 단독 수행했고 네트워크·스토리지·카탈로그·계보·오케스트레이션·분산 학습·신원까지 12개 Pulumi 스택 전부를 직접 만졌습니다.
· 6개월간 10노드 · 상시 pod 235개 · 사내 서비스 23종을 프로덕션에서 운영 중입니다. 머지 PR 678건 · 커밋 1,204건을 냈습니다.
· ETL 파이프라인은 별도 저장소에서 커밋 1,599건을 냈습니다. 제품 공용 프레임워크와 CAST · MIMIC-IV · 운영 유지보수 파이프라인을 직접 작성했습니다.

[데이터 — 사람 한 명에게 걸려 있던 병목을 없앴습니다]
· 기존에는 연구자가 데이터 과학자 한 명에게 요청하면, 하드코딩된 스크립트를 SSH로 수 시간 실행해 파일로 넘기는 구조였습니다. 담당자가 자리를 비우면 작업이 멈췄고 재현·계보·버전이 모두 없었습니다.
· Airflow 3.x + dbt(Cosmos) + Apache Iceberg로 Bronze/Silver/Gold 변환을 스케줄 자동 실행으로 바꾸고 DataHub에 테이블 단위 계보를 자동 기록했습니다. 요청·대기 없이 연구자가 직접 조회합니다.
· 도메인 ETL은 연구자가 얹고 실행·계보·검증·재시도는 플랫폼이 책임지는 분담 구조를 정착시켰습니다.

[기반 — 학습 데이터 전달 시간을 25배 줄였습니다]
· 네트워크·스토리지를 재설계해 iperf3 실측 93.7Mbps → 2.5Gbps, 8TB 기준 8.4일 → 7.8시간으로 단축했습니다.
· SeaweedFS(S3 호환) 위 Iceberg 레이크하우스에 NVMe/HDD 티어 분리를 적용했습니다.
· PostgreSQL + pg_duckdb로 Iceberg를 ad-hoc SQL로 엽니다. pyiceberg 코드를 작성해야 하던 분석을 브라우저 SQL 한 줄로 바꿨습니다.

[학습 — 분산 학습 기반을 구축했습니다]
· KubeRay로 사양이 제각각인 GPU 10장을 단일 풀로 묶습니다. 여기에 CUDA·PyTorch·ONNXRuntime 버전을 고정한 단일 워커 이미지와 사내 SDK 제출 API를 얹어 학습 환경을 일원화했습니다(자동 checkpoint·중단 지점 재개 지원).
· 도입 단계이며 연구 코드 이관이 남은 과제입니다. 이관을 막는 원인은 실측으로 규명했습니다.

[설계 — 재현성 아키텍처는 기존 워크플로 정량 분석에서 나왔습니다]
· 연구 저장소를 조사했습니다. 원격 브랜치 51개, 출력이 저장된 노트북 셀 67~88%, 실험 기록은 로컬 폴더에 고립돼 있었습니다.
· 원인은 도구 부재가 아니었습니다. "결과에 좌표가 없다"가 원인이라고 특정했습니다.
· 재현성 계약(동결 도구 · manifest 스키마 · 무결성 검증 CLI)을 설계·구현했습니다. 데이터셋에 버전 · 내용 해시 · 코드 커밋 · 환경 lock · 시드를 실행 시점에 박는 계약입니다. MLflow 트래킹·모델 레지스트리는 그 좌표의 저장소로 배치했습니다.

[접근 — 공유 비밀번호를 단일 신원으로 통합했습니다]
· Dex(GitHub OIDC) + oauth2-proxy로 사내 서비스 23종에 SSO를 적용하고 같은 신원을 Kubernetes RBAC까지 연결했습니다.
· GPU 서버에 직접 SSH하던 개발 방식을 JupyterHub 브라우저 개발환경으로 대체했습니다(개인 볼륨 · egress 정책 격리 · 명령 한 줄 부트스트랩).

[판단 — 실측으로 GPU 증설 결정을 전환했습니다]
· 증설 검토 요청에 대해 DCGM·Prometheus로 10일간 측정한 결과, 가동률 5.3% · 대기 작업 0건이었습니다.
· 병목은 용량이 아니라 유휴 세션이 점유한 1,112 GPU-시간(점유 시간의 91%)이었습니다. 구매 대신 할당 회수로 방향을 전환했습니다.

[방식 — 속도를 검증 장치로 받쳤습니다]
· AI 코딩 에이전트를 상시 투입해 1인 처리량을 팀 규모로 끌어올렸습니다.
· 같은 기간에 SDK 단위 테스트 719건, 태그/버전 불일치와 개인키 커밋을 막는 CI 게이트·pre-commit 훅, 실패 기록 23건 · PRD 30건을 함께 축적했습니다.
```

## 줄일 때

원티드는 길이에 관대하지만 읽는 사람은 그렇지 않다. 잘라야 하면 이 순서다.

1. `[접근]` 의 두 번째 항목(devenv) — `[학습]` 과 겹쳐 보인다
2. `[기반]` 의 티어 분리 항목 — 25배 문장이 이미 충분히 세다
3. `[소유 범위]` 의 세 번째 항목을 두 번째에 병합

⚠ `[판단]` 과 `[방식]` 은 **남긴다.** 인프라 지원자 대부분이 못 쓰는 줄이다.
